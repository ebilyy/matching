# 0002 — Upload the own catalog via manager UI, reusing the price-import pipeline

- **Status:** Accepted
- **Date:** 2026-10-01
- **Deciders:** gene.bilyy@gmail.com (Architect, Socratic pass of sdlc:architecture-design)

## Context

US-01 виходить з того, що власні товари «вже є в системі», а PRD §3 виніс спосіб їх потрапляння за межі фічі. Але product-matching — окремий застосунок без інтеграції з платформами магазинів (idea-brief §15), тож без каналу завантаження каталогу зіставляти нема з чим. PRD §8 OQ #1 вимагав закрити це питання до architecture-design.

## Decision drivers

- PRD §8 OQ #1: «Як власні товари пілотних магазинів потрапляють у систему?» — due перед architecture-design.
- Goal 1 (PRD §2): менеджер працює без ручного зведення; залежність від оператора на кожне оновлення каталогу суперечить цьому.
- Бюджет 4 людино-тижні (SAD §2) — канал має перевикористати розбір прайсів, а не дублювати його.

## Considered options

1. **CLI-імпорт оператора** — команда `catalog:import --shop --file` поверх модуля розбору; без UI.
2. **Завантаження каталогу менеджером у UI** — той самий майстер «файл → розмітка колонок», що й для прайсу, але для власного каталогу.
3. **Відкласти в §11 як Open question.**

## Decision outcome

**Chosen:** Option 2 — завантаження менеджером у UI. Магазин самостійний з першого дня пілоту; розбір, розмітка колонок і ліміти безпеки спільні з імпортом прайсів, тож додатковий обсяг обмежується окремою цільовою моделлю (власний товар) і екраном.

## Consequences

**Positive**
- Немає ручного кроку оператора на кожне оновлення каталогу.
- Один конвеєр розбору файлів (ліміти, захист від архівних бомб, формули не виконуються) — один об'єкт для security review.

**Negative**
- Розширює обсяг понад PRD §3 non-goal («завантаження власного каталогу — поза межами») — орієнтовно +2–3 дні в бюджеті без запасу.
- З'являється продуктове питання: що робити з власним товаром, який зник із нового завантаження каталогу, але має зіставлення (див. SAD §11).

**Neutral**
- Інтеграцію з API платформ магазинів (Horoshop, Prom тощо) можна додати пізніше як ще одне джерело того ж конвеєра.
